# Rilis web/admin dan autentikasi email

Dokumen ini menyiapkan deployment; tidak mengizinkan perubahan hostname API yang dipakai mobile atau IoT.

## Perubahan kontrak

- Endpoint lama `/users/register`, `/users/login`, `/users/me`, `/sensor/`, dan endpoint mobile lainnya tetap tersedia.
- Payload serta response schema `/sensor/` tidak berubah.
- Saat device `maintenance` atau `inactive`, `/sensor/` tetap merespons `200` dengan schema lama (`id=0`) tetapi tidak menyimpan pembacaan.
- Akun lama dimigrasikan sebagai `email_verified=true`; login dan bearer token lama tetap berlaku.
- Endpoint web baru memakai suffix baru: `/register-web`, `/login-web`, verifikasi email, dan reset password.

## 1. Gate sebelum menyentuh server

- [ ] Backend dan frontend sudah berada pada commit/tag rilis yang diketahui.
- [ ] `python -m unittest discover -s tests -v` lulus.
- [ ] `npm ci && npm run build` lulus.
- [ ] Image backend dan frontend dibangun dari commit yang sama dengan hasil tes.
- [ ] Backup PostgreSQL terbaru berhasil direstore pada staging.
- [ ] Token mobile lama berhasil memanggil `/users/me` pada staging.
- [ ] IoT canary aktif mendapat HTTP 200 dan menambah tepat satu row.
- [ ] IoT canary maintenance mendapat HTTP 200 dan tidak menambah row.

## 2. Secret produksi

Salin `deployment/stage2/app.env.example` menjadi `deployment/stage2/secrets/app.env` pada server, isi nilainya, lalu batasi permission ke operator deployment. Jangan salin `google_sandi_aplikasi.txt` ke server atau image.

Nilai wajib:

- `DATABASE_URL`: PostgreSQL production.
- `ADMIN_API_KEY`: nilai production yang sedang dipakai.
- `SMTP_EMAIL` dan `SMTP_APP_PASSWORD`: akun Gmail pengirim.
- `FRONTEND_URL=https://aquanotes.farlabs.my.id`.
- `CORS_ORIGINS=https://aquanotes.farlabs.my.id`; jangan gunakan `*`.
- `START_BACKGROUND_TASKS=true`: hanya pada satu container API.

## 3. Backup dan migrasi aditif

```bash
pg_dump --format=custom --file=aquanotes-before-web-admin.dump "$DATABASE_URL"
docker compose -f deployment/stage2/compose.yml build api
docker compose -f deployment/stage2/compose.yml run --rm api \
  python -m scripts.migrate_release_20260827 --apply
docker compose -f deployment/stage2/compose.yml run --rm api \
  python -m scripts.preflight_release --check-smtp
docker compose -f deployment/stage2/compose.yml run --rm \
  -v ./secrets/web-super-admin.txt:/run/secrets/web-super-admin.txt:ro api \
  python -m scripts.set_admin_role --credentials-file /run/secrets/web-super-admin.txt
```

Migrasi hanya menambah/memperlebar schema: `users.role`, `users.email_verified`, `devices.deactivation_scheduled_at`, `devices.status VARCHAR(20)`, serta tabel admin/email. Script juga menyelaraskan sequence PostgreSQL setelah import lama.

## 4. Urutan rollout

1. Deploy backend lebih dahulu; biarkan hostname API mobile/IoT tetap sama.
2. Tunggu `/health` HTTP 200 dan status container healthy.
3. Uji token mobile lama, `/monitoring/`, `/devices/status/`, serta satu payload IoT canary.
4. Set device canary ke maintenance, kirim payload yang sama, pastikan HTTP 200 dan row sensor tidak bertambah; aktifkan kembali.
5. Pantau 4xx/5xx, latency, FCM, dan timestamp seluruh device minimal satu interval penuh.
6. Deploy image frontend dengan `API_UPSTREAM` menuju origin API internal.
7. Uji registrasi email, verifikasi, login web, lupa password, login admin, serta refresh deep-link SPA.

## 5. Cloudflare

Pada Cloudflare Zero Trust > Networks > Tunnels > Public Hostnames, tambahkan:

- Subdomain: `aquanotes`
- Domain: `farlabs.my.id`
- Service type: `HTTP`
- URL: `http://192.168.10.64:8080`
- Path: kosong

Tunnel membuat DNS CNAME ter-proxy otomatis. Jika dibuat manual, arahkan CNAME `aquanotes` ke `<TUNNEL_ID>.cfargotunnel.com`, bukan ke IP private. Aktifkan `Always Use HTTPS`, lalu buat Cache Rule `Bypass cache` untuk `aquanotes.farlabs.my.id/api/*`.

## 6. Smoke test wajib

- [ ] `GET /health` = 200 dan `{"status":"ok"}`.
- [ ] `GET /openapi.json` = 200.
- [ ] Bearer token lama tetap valid.
- [ ] Login mobile lama tetap mengembalikan `access_token` dan `token_type`.
- [ ] UID tidak dikenal pada `/sensor/` tetap 404.
- [ ] Device aktif menyimpan satu row per payload.
- [ ] Device maintenance/inactive tidak menyimpan row dan tetap HTTP 200.
- [ ] Akun lama dapat login tanpa verifikasi ulang.
- [ ] Akun web baru tidak dapat login sebelum verifikasi.
- [ ] Reset password mencabut seluruh sesi lama.
- [ ] Link email memakai hostname HTTPS web production.

## 7. Rollback

Schema rilis bersifat aditif sehingga image backend sebelumnya dapat dijalankan tanpa menghapus kolom/tabel baru.

1. Hentikan rollout frontend dan kembalikan image frontend sebelumnya.
2. Kembalikan image backend sebelumnya, dengan `DATABASE_URL`, Firebase secret, dan hostname API yang sama.
3. Jangan restore database bila write baru sudah diterima; schema tambahan boleh tetap ada.
4. Restore dump hanya jika ada kerusakan data dan seluruh write sudah dihentikan serta delta telah direkonsiliasi.
5. Verifikasi token lama, ingestion IoT, monitoring, FCM, dan background task setelah rollback.

Kriteria rollback: 5xx berkelanjutan, token lama gagal, sensor aktif tidak tersimpan selama satu interval, notifikasi ganda, atau timestamp device berhenti bergerak.
